# 真实本地模型 HTTP 验收

日期：2026-10-14。使用最终打包的 Spring Boot 应用、真实 MySQL 8.0.41，以及 Ollama 0.40.3 提供的 Qwen3 4B Instruct 本地模型。请求经过实际登录、CSRF、工单权限、Java Agent 循环、工具执行、答案校验和数据库持久化，没有用脚本响应替代模型。

本轮模型上游为 `qwen3:4b-instruct`，本地导入别名为 `portfolio-qwen3-4b-instruct`。应用设置：

```text
SUPPORTDESK_OLLAMA_URL=http://127.0.0.1:11434
SUPPORTDESK_OLLAMA_MODEL=portfolio-qwen3-4b-instruct
SUPPORTDESK_THOUGHT_IN_CONTENT=false
```

模型请求参数为 `temperature=0`、`num_predict=512`、`num_ctx=8192`、`think=false`。模型轮次与工具调用共享八步预算，总时限 90 秒。仅使用虚构企业、演示订单和内置售后资料；未连接真实商家或实际退款系统。

## 预先固定的三条独立问题

问题及预期在执行前保存，执行后未改提示词、校验器、工具或预期，也未通过重试挑选成功结果。每条使用一张新建工单、同一份演示售后资料和当前工单绑定的已交付订单。

| 编号 | 问题 | 实际工具轨迹 | 单次耗时 | 结果 |
| --- | --- | --- | ---: | --- |
| H1 | 按工作区的演示规范，换货诉求从登记到关闭应该怎样处理？请给出资料依据。 | `search_policy → lookup_order → answer` | 7.66 秒 | 通过本条预期；返回流程及真实原文引用 |
| H2 | 这张工单关联的订单当前处于什么状态？只查当前订单，不用介绍售后规则。 | `lookup_order → answer` | 0.86 秒 | 通过本条预期；回答“订单当前状态为已交付。”，无伪造资料引用 |
| H3 | 请核对当前订单与售后规则，替客服拟一条发给客户的回复，说明后续人工核对安排。先生成待人工确认草稿，不要自动发送。 | `lookup_order → search_policy → answer` | 3.05 秒 | **未完成草稿任务**；模型没有调用 `propose_reply` |

H1 返回 `after-sales.md` 第 1–4 行原文，并在答案中实际标出 `[1]`。内容与内置演示流程一致：先核对订单与商品批次，进入人工核对流程，不承诺自动换货或退款，记录结果、回复客户并确认完成后关闭工单。H1 额外查了一次绑定订单，不是最少工具路径。

H3 的 HTTP 状态是 201，表示一条助手运行记录已保存；它的 `state=none`、`reply=null`，不能算作草稿生成成功。它给出了有资料依据的说明文字，却没有产生可以确认发布的草稿。因没有真实 `pending` 草稿，本条没有调用发布接口。

三条请求前后的工单消息数都为 0，模型均未自动发送客户消息。两条完成、一道草稿任务未完成，是这三个固定问题的观察结果，**不能换算为模型通用准确率、稳定性承诺或生产性能结论**。引用结构校验也不等于语义真实性保证。

## 单独的显式工具开发验证

为区分“模型没有遵从自然提问”与“工具及发布链路不能工作”，另执行一条明确写出工具名的开发请求。这不是独立验收问题，结果单独记录，不替换 H3。

请求原文：

> 请先用 lookup_order 核对当前工单订单，再用 search_policy 查询售后规则，随后必须调用 propose_reply 生成一份待人工确认的中文客户回复草稿。不要仅在最终回答里描述草稿。完成后按约定返回答案。

这次真实模型在 4.64 秒内执行 `lookup_order → search_policy → propose_reply → answer`，返回非空回复和 `state=pending`。生成后消息数仍为 0。

随后使用同一原客服的两个独立登录会话，并发提交该草稿的人工确认接口请求，携带同一工单版本：

- 返回状态分别为 200 和 409。
- 草稿最终状态为 `published`，客户能读取到且仅有一条回复。
- 工单共两条审计事件：创建及回复，没有重复发布事件。

这验证了真实模型能够调用草稿工具，以及待确认草稿的一次性发布链路；没有把 API 确认请求描述为已经过真实客服的内容审核。回复文案仍需要使用者核对和润色。

## 当前限制与复现边界

自然语言草稿任务存在漏调用 `propose_reply` 的情况，当前不能声称“任意提问都能稳定生成草稿”。使用者应查看工具轨迹、`state` 与草稿区域；只有真正出现待确认草稿，才能走人工确认操作。没有草稿时可人工编写回复，或明确要求执行生成草稿工具。

本轮没有为追求成功率降低引用校验、添加自动工具调用、绕过权限、伪造响应或自动发送消息。耗时为本机串行的一次观测，包含各请求实际推理开销，不能与其他机器直接比较。
