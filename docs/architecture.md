# 一次请求怎样走完

```text
客户 / 客服的 Vue 页面
        │ 同源请求、会话 Cookie、写入时携带 CSRF 令牌
        ▼
Spring Security + 本机请求边界检查
        ▼
Controller：检查输入，从会话取得账号
        ▼
SupportService：检查企业 / 客户范围、状态与版本
        ▼
JDBC 事务 ── H2 文件库 / MySQL + Flyway
```

客户提交工单时必须选择自己的有效订单。客服回复时，服务先锁住工单行，再核对页面版本；回复、工单版本和事件记录在同一事务中保存。另一个客服提交旧版本时得到 409，页面要求刷新。

## AI 接在业务旁边

客服打开某张工单并提问。Java 先取得当前账号有权访问的工单、绑定订单、资料和有限消息，将这些内容作为一次运行的快照；等待模型时不持有工单数据库锁。

```text
客服问题 + 有权限的业务快照
        ▼
本机 Ollama 模型选择工具
        ▼
Java 校验工具名和参数
        ├─ search_policy：只检索本企业资料
        ├─ lookup_order：只读取当前工单绑定的订单
        └─ propose_reply：只生成草稿
        ▼
工具观察结果返回模型 → 校验答案和来源 → 保存运行记录
```

`search_policy` 按原始行号切分资料，以 BM25 计算词法相关性。它不调用向量模型。模型的引用编号必须对应本次实际返回的来源；这一约束不等于答案语义正确。

草稿保存原客服、工单版本和十分钟到期时间。客服点击确认发布时，事务按“工单行 → 草稿行”的顺序加锁，再检查身份、版本、有效期和 pending 状态。正式回复写入与草稿消费共同提交，因此重复发布、其他客服代发和旧版本草稿会被拒绝。

## 浏览器状态也要检查

页面的账号、CSRF 令牌和工作区状态只在内存中保存。退出或切换账号会清空旧工作区。异步请求还带有账号与工单选择代次，较晚返回的旧请求不能覆盖新页面；即使按 A → B → A 切换工单，旧 A 请求也会被丢弃。

前端的按钮限制帮助用户操作，服务端仍重新执行所有权限、版本和草稿状态检查。两者分别承担交互提示与数据约束。
