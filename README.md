# SupportDesk AI · 售后工单与 AI 客服协作平台

一个 Java + Vue 全栈学习项目：客户查看订单、提交售后问题，客服回复并跟进处理进度。可选的本地 AI 助手帮助查资料、核对当前订单和起草回复，客服确认后才会把草稿发到工单中。

项目使用原创的虚拟企业、账号、商品和售后规则，借助 AI 辅助设计、编码与检查，适合学习后继续修改和演示。没有真实客户、企业上线经历或商业效果数据。

## 可以演示什么

- **客户侧**：查询自己的订单、提交售后工单、补充问题、查看回复，将已解决的工单重新打开。
- **客服侧**：搜索和筛选本企业工单，回复客户，按“待处理 → 处理中 → 已解决”推进状态，维护共享售后资料。
- **多人协作**：每次修改携带版本号；两名客服同时修改旧版本时，一个成功，另一个收到冲突提示并需要刷新。回复、版本变化和事件记录放在同一事务中。
- **数据范围**：客户只能访问自己的订单与工单，客服只能访问本企业数据。服务端从登录会话取得身份，并在数据库查询中检查范围。
- **资料检索**：将资料切成保留原始行号的片段，以 BM25 检索并展示文件名、行号和原文。
- **本地 Agent**：模型可以调用 `search_policy`、`lookup_order` 和 `propose_reply` 三个工具。读取订单时只能读取当前工单绑定的订单；草稿需要人工确认，过期、重复发布或版本过时都会被拒绝。

系统没有支付、退款、寄送或向外发送邮件的能力。普通工单流程和资料检索演示不需要配置模型。

## 技术组成

| 层次 | 实现 |
| --- | --- |
| 页面 | Vue 3、Vite；会话状态只保存在内存，文本使用普通插值渲染 |
| 服务 | Java 21、Spring Boot、Spring Security、Spring JDBC、Bean Validation |
| 数据 | 默认 H2 文件数据库；可选 MySQL 8，使用 Flyway V1/V2 迁移 |
| AI | Java 直接调用本机 Ollama；工具白名单、来源引用、人工发布 |
| 验证 | Java 真实 HTTP 场景测试、Node 测试；可选独立 MySQL 场景测试 |

## 开始运行

准备 Java 21、Maven 和 Node.js 22.12 及以上版本。按照 [快速开始](docs/quickstart.md) 构建前端和后端，设置自己选择的演示密码，再运行 JAR。默认打开 `http://127.0.0.1:8080`，不依赖付费 API 或第三方登录。

界面提供六个虚拟账号。第一次启动新数据库时，它们使用同一个由你设置的 `SUPPORTDESK_DEMO_PASSWORD`；仓库不提供固定密码。重启不会重置已保存的密码。

| 虚拟企业 | 客户 | 客服 |
| --- | --- | --- |
| 青禾数码 | `demo_customer`、`demo_customer2` | `demo_agent`、`demo_agent2` |
| 星桥文具 | `demo_other` | `demo_other_agent` |

## 检索演示与模型模式

页面默认的“资料检索演示”只执行检索并展示摘录，**没有调用大模型，也不会产生回复草稿**。

配置 `SUPPORTDESK_OLLAMA_MODEL` 后才能选择模型模式。该模式由模型决定调用工具，再根据工具结果作答；服务端限制工具参数、步骤、用时和响应大小。模型仍可能失败或引用不恰当，来源校验只保证引用对应本次检索的资料片段，不证明答案语义一定正确。真实模型表现应以注明模型、环境和结果的实际运行记录为准，不能由脚本测试推算准确率。
